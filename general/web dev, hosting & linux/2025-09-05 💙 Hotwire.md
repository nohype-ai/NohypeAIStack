### Turbo: Handling Navigation and Updates
Turbo is the core of Hotwire's dynamic capabilities, using browser-native APIs to make apps feel like single-page applications (SPAs) without a full client-side framework.

- **What the Browser Sees**:
  - Initial page load: Standard HTML with `<script>` tags that include the Turbo JavaScript library (e.g., via a CDN or bundled script).
  - Responses from the server: HTML fragments or full pages, often delivered over HTTP (via fetch requests) or WebSockets/SSE (Server-Sent Events) for real-time updates. These may include special elements like `<turbo-frame>` for partial updates or `<turbo-stream>` for targeted DOM changes.
  - No JSON data structures; everything is pre-rendered HTML ready for direct insertion.

- **What the Browser Does**:
  - Loads the Turbo script, which hooks into browser events (e.g., link clicks, form submissions) and APIs (e.g., History API for URL changes, Fetch API for requests).
  - For navigation: When a user clicks a link or submits a form, Turbo intercepts the event, prevents the default browser reload, makes an asynchronous request to the server, receives HTML, and swaps or merges it into the current DOM (e.g., replacing `<body>` content while keeping the `<head>` and document object intact).
  - For partial updates: Using frames or streams, the browser extracts specific HTML chunks and applies mutations like appending, replacing, or removing elements without reloading the whole page.
  - Handles caching, redirects, and errors natively, ensuring fast, seamless experiences.

- **How Hotwire (Turbo) Interfaces with the Browser**:
  - Turbo acts as a lightweight JavaScript layer that listens for DOM events and manipulates the page using standard browser methods (e.g., `element.replaceWith()` for swaps).
  - It leverages WebSockets or SSE for push updates, where the server broadcasts `<turbo-stream>` elements, and the browser processes them to mutate the DOM in real-time.
  - No custom JavaScript is required from the developer for core functionality; Turbo handles the interface transparently, falling back to standard browser behavior if JavaScript is disabled (progressive enhancement).

#### Specific Turbo Components:
- **Turbo Drive (Navigation)**: Intercepts same-domain link clicks and form submits, uses Fetch to get HTML, updates the URL via History API, and renders by merging/replacing DOM parts. This avoids full page reloads, making apps feel instant.
- **Turbo Frames (Partial Pages)**: Wraps page sections in `<turbo-frame>` tags. The browser loads or updates only that frame's content asynchronously, keeping the rest static. Frames can lazy-load via a `src` attribute.
- **Turbo Streams (Real-Time Updates)**: Server pushes actions (e.g., "append", "remove") wrapped in `<turbo-stream>` tags over WebSockets. The browser applies these directly to targeted elements by ID, reusing server templates without client-side logic.

### Stimulus: Adding Interactive Behaviors
Stimulus complements Turbo by providing a way to attach JavaScript behaviors to HTML elements without a heavy framework.

- **What the Browser Sees**:
  - HTML with data attributes like `data-controller="example"`, `data-action="click->example#handleClick"`, and `data-target="example.output"`.
  - These attributes are embedded in the server-rendered HTML; no separate JS files or bundles are visible beyond the Stimulus script include.

- **What the Browser Does**:
  - Loads the Stimulus script, which scans the DOM continuously for `data-controller` attributes.
  - When it finds one, it instantiates a controller class (a plain JavaScript object) and connects it to the element.
  - Responds to events: For example, a click triggers an action method in the controller, which can update targets (specific sub-elements) or values (data props) in the DOM.

- **How Hotwire (Stimulus) Interfaces with the Browser**:
  - Stimulus uses mutation observers to watch for new elements, automatically wiring up controllers as the DOM changes (e.g., after Turbo updates).
  - It bridges HTML to JS via attributes: Actions link events to methods, targets reference child elements for manipulation, and values allow reading/writing data that can trigger updates.
  - This keeps JavaScript scoped and reusable, with the browser handling native events and DOM ops—no virtual DOM or state management needed.

In summary, the browser primarily sees and processes standard HTML enhanced with minimal scripts and attributes. Hotwire interfaces by injecting a thin JS layer that intercepts events, fetches server-rendered HTML, and performs targeted DOM updates, all using built-in browser features for efficiency and simplicity.<grok:render card_id="0698c0" card_type="citation_card" type="render_inline_citation">
